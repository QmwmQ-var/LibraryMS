本文是仓库上传到 GitHub 之后的**执行清单**：先做第 1、2 节的网页设置（只有仓库管理员能做），再按第 3 节推送，其余成员按第 4 节上手。分支与模块边界以 [`团队分工与协作.md`](团队分工与协作.md) 为准。

- 仓库地址：`git@github.com:QmwmQ-var/LibraryMS.git`（HTTPS：`https://github.com/QmwmQ-var/LibraryMS.git`）
- 已上传内容：`main`、`develop`、`feature/platform-auth`、`feature/catalog`、`feature/readers`、`feature/circulation`、`feature/analytics`、`feature/reservations`，以及标签 `v1.0.0`
- 当前基线：`main` 已包含 `.github/CODEOWNERS`、PR/Issue 模板、CI 工作流与 `CONTRIBUTING.md`

## 1. GitHub 网页端设置（管理员操作，共 4 步）

### 1.1 邀请成员

`Settings → Collaborators → Add people`，逐个邀请另外 4 位成员（用 GitHub 用户名或邮箱）。

| 角色 | 权限 | 说明 |
| --- | --- | --- |
| 模块负责人 B/C/D/E | `Write` | 能推自己的 `feature/*` 并开 PR |
| 当周集成人 | `Write` | 合并 PR 到 `develop`，不需要 Admin |
| 仓库管理员 A | `Admin` | 改保护规则、加人、打 tag |

### 1.2 保护 `main` 与 `develop`

`Settings → Branches → Add branch protection rule`。

`main`（严格）：

- Branch name pattern：`main`
- ✅ Require a pull request before merging（Required approvals：**1**）
- ✅ Require review from Code Owners
- ✅ Dismiss stale pull request approvals when new commits are pushed
- ✅ Require status checks to pass before merging，勾选 CI 的两个检查：`后端 · 测试`、`前端 · 构建`
- ✅ Require conversation resolution before merging
- ✅ Do not allow bypassing the above settings（含管理员）
- ❌ 不要勾 Allow force pushes / Allow deletions

`develop`（稍宽）：

- Branch name pattern：`develop`
- ✅ Require a pull request before merging（Required approvals：**1**）
- ✅ Require status checks：`后端 · 测试`、`前端 · 构建`
- ❌ 允许合并（Merge commit 或 Squash，二选一，团队统一即可，建议 **Squash** 保持历史线性）

> 私有仓库的部分保护选项需要 GitHub Pro；课程项目建议把仓库设为 **Public**，既免费又能让老师直接看代码与 Actions 记录。改公开前确认仓库里没有真实口令（当前 `application.yml` 全部用环境变量占位，可直接公开）。

### 1.3 打开 Actions

`Settings → Actions → General`：

- Actions permissions 选 **Allow all actions and reusable workflows**；
- Workflow permissions 选 **Read repository contents permission**（CI 只读即可）。

推送 `.github/workflows/ci.yml` 后，`Actions` 标签页会出现 `CI` 工作流；到 `develop` 上跑一次，确认两个 job 都是绿色。

### 1.4 仓库信息

`Settings → General` 顶部填 Description（如"高校图书管理系统 · Vue 3 + Spring Boot 3"），Topics 建议：`vue3`、`spring-boot`、`mybatis-plus`、`library-management`、`course-design`。

## 2. 替换 CODEOWNERS 占位账号

`.github/CODEOWNERS` 里的 `@member-a` … `@member-e` 是占位符，**必须替换成真实用户名**，否则 PR 不会自动指派评审人。

假设成员账号如下（示意）：

| 占位符 | 真实账号 |
| --- | --- |
| `@member-a` | `@zhangsan` |
| `@member-b` | `@lisi` |
| `@member-c` | `@wangwu` |
| `@member-d` | `@zhaoliu` |
| `@member-e` | `@sunqi` |

替换步骤：

```bash
git switch main
# 用编辑器把 5 个占位符全局替换为真实账号
git add .github/CODEOWNERS
git commit -m "chore(repo): 替换 CODEOWNERS 成员账号"
git push origin main
```

验证：随便开一个改到 `frontend/src/views/book/` 的 PR，右侧 Reviewers 应自动出现 B 的账号。若没有，检查账号是否为仓库协作者、`CODEOWNERS` 是否在 `main` 分支的 `.github/` 下。

## 3. 推送本次新增的协作文件

这些文件已在本地提交但**尚未推送**，由你执行：

```bash
# 1. 确认 8 个分支都带上了这次提交
git log --oneline -3
git branch -vv

# 2. 推送主干与集成分支
git push origin main
git push origin develop

# 3. 推送 6 个 feature 分支（名称照抄）
git push origin feature/platform-auth feature/catalog feature/readers feature/circulation feature/analytics feature/reservations

# 4. 需要新标签时
git push origin --tags
```

网络不稳定时（本机访问 GitHub 的 443 端口常被重置）命令会报 `Connection reset by peer`：**直接重试同一命令 2–3 次**即可，已推送成功的分支重试不会有副作用。

## 4. 成员第一次上手

每人只需执行一次：

```bash
# 1. 克隆（SSH 不通就用 HTTPS 地址）
git clone git@github.com:QmwmQ-var/LibraryMS.git
cd LibraryMS

# 2. 切到自己负责的分支
git switch feature/catalog          # 换成自己的分支

# 3. 装依赖并启动（Mock 模式，不需要数据库）
cd frontend
npm install
npm run dev                          # http://localhost:5173
```

后端同学额外执行：

```bash
cd backend
./mvnw spring-boot:run               # Windows: mvnw.cmd spring-boot:run
# 首次需建库并导入 database/schema.sql、database/data.sql
```

上手自查（能在自己机器上完成即算就绪）：

- [ ] 登录页可用，管理员与读者两种角色都能进入；
- [ ] `cd backend && ./mvnw test` 全绿；
- [ ] `cd frontend && npm run build` 成功；
- [ ] `git switch` 到自己分支后 `git status` 干净。

## 5. 日常协作循环

```text
改自己模块 → 本地自测 → commit → push feature/xxx
   → 开 PR（base=develop，按模板填自测结果）
   → CI 绿 + 对应负责人 Approve
   → 当周集成人 Squash merge → develop 自动更新
   → 每周五 develop 验证主链路 → PR 到 main → 打 tag
```

具体命令：

```bash
# 每天开始
git switch feature/catalog
git pull origin feature/catalog

# 提交
git add -A
git commit -m "feat(book): 支持按出版年份过滤"
git push origin feature/catalog
```

发布周版本（集成人执行）：

```bash
git switch develop
git pull origin develop
git tag -a v0.2-circulation -m "流通与罚款模块验收版"
git push origin v0.2-circulation
# develop -> main 走 PR，合并后在 main 上重复打 tag
```

**预约模块的合并路径**：`feature/reservations`（提交 `dc1a86e`，含后端预约排队/到书留书/领取闭环与前端两个页面）尚未进入集成线，D 负责：

1. PR `feature/reservations` → `feature/circulation`（补齐 `docs/接口清单.md`、`docs/数据库设计.md` 的预约章节）；
2. 再从 `feature/circulation` 开 PR 到 `develop`；
3. 合并后删除 `feature/reservations`（`git push origin --delete feature/reservations`）。

## 6. 故障排查

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| `Connection reset by ... port 443` | 到 GitHub 的 SSH 连接被重置 | 重试 2–3 次；仍失败改用 HTTPS 克隆并配置 PAT |
| `ssh: connect to host github.com port 22: Connection timed out` | 22 端口被拦 | 在 `~/.ssh/config` 写：`Host github.com` / `Hostname ssh.github.com` / `Port 443` / `User git` |
| `Permission denied (publickey)` | 公钥未加到 GitHub | `ssh -T git@github.com` 自测；把 `~/.ssh/id_ed25519.pub` 加到 GitHub → SSH keys |
| HTTPS 推送要求密码 | GitHub 已禁用账号密码 | 用 Personal Access Token 当密码，或改用 SSH |
| `mvnw` 下载 Maven 失败（TLS/证书） | 本机网络对 Maven Central 不稳 | 重试；或临时用本地 Maven（`mvn -s` 指定 settings），不影响 CI |
| 前端起不来，`Cannot find module` | 依赖没装或 Node 版本过低 | `node -v` 确认 ≥18，`npm ci` 重装 |
| 页面没有数据 | Mock 未开启 | 检查 `.env.development` 的 `VITE_USE_MOCK=true`；连真实后端用 `npm run build:backend` |
| CI 红：`后端 · 测试` | 单测/契约被改坏 | 本地 `./mvnw test` 复现，修好再推 |
| CI 红：`前端 · 构建` | 语法错误或依赖缺失 | 本地 `npm ci && npm run build` 复现 |
| PR 没有自动指派评审人 | CODEOWNERS 占位符未替换 | 见第 2 节 |
