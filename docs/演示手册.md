# 演示手册（约 8 分钟）

> 默认使用前端 Mock API，不需要数据库和 Java 环境。
> 开始前执行 `cd frontend && npm install && npm run dev`，打开终端显示的地址。

## 0. 准备

| 身份 | 账号 | 密码 | 适合演示 |
| --- | --- | --- | --- |
| 图书管理员 | `admin` | `admin123` | 馆藏管理、流通办理、罚款、统计 |
| 本科生读者 | `2023001` | `reader123` | 查询、借阅、续借、罚款 |
| 研究生读者 | `2022008` | `reader123` | 不同借阅额度 |
| 教师读者 | `2021012` | `reader123` | 90 天借期 |

登录页提供「快速体验」卡，点击即自动填入账号，适合现场操作。
如果之前演示改乱了数据，可点击登录页底部「重置演示数据」恢复初始种子。

## 1. 登录与角色差异（1 分钟）

1. 打开登录页，简单展示左侧品牌与右侧快速体验卡；
2. 点击“图书管理员”卡，登录；
3. 指出侧边栏和顶栏：
   - 管理员：首页、图书管理、分类管理、读者管理、流通办理、罚款管理、统计报表；
   - 顶栏消息通知、角色身份、全局搜索；
4. 退出，用 `2023001` 登录；
5. 指出读者菜单只有 首页、馆藏检索、我的借阅、我的罚款、个人中心。
6. 说明：前端按角色隐藏菜单只是体验，后端每个接口都做了鉴权。

## 2. 图书馆员视角（5 分钟）

### 2.1 仪表盘

- 今日馆务、馆藏品种、当前在借、注册读者、待缴罚款；
- 借阅趋势、分类构成、在借与临期、今日待办、热门借阅、最近动态；
- 通知铃铛中展示逾期、罚款、低库存提醒。

### 2.2 馆藏管理

1. 进入「图书管理」；
2. 输入“三体”搜索，展示多条件组合查询；
3. 点开图书详情抽屉，说明馆藏信息、库存、借阅须知；
4. 点击「新增图书」，展示表单校验；新增后系统自动以书名定位到刚录入的书；
5. 编辑/删除按钮根据角色显示，删除有未还副本的图书会被后端拒绝。

### 2.3 分类与读者

- 分类页展示每个分类的品种、馆藏量、借阅热度，支持 CRUD；
- 读者页展示借阅证状态、读者类型、额度进度、待缴罚款；
- 打开读者详情，展示借阅证、在借清单，可切换挂失/注销状态；
- 说明：挂失/注销读者借书会被业务层拦截。

### 2.4 流通办理与罚款

1. 进入「流通办理」；
2. 点击右上角「快速体验」，系统读取 2023001 读者；
3. 选一本可借图书 → 确认借阅 → 展示成功弹窗与应还日期；
4. 在右侧“还书通道”找到一条记录 → 还书；
5. 如果逾期，结果弹窗展示“逾期天数 × 0.50 元”生成的罚款；
6. 打开「罚款管理」，筛选待缴，确认一笔缴纳；说明罚款幂等、不能重复支付；
7. 借阅台账支持读者、图书、日期、状态组合查询。

### 2.5 预约队列与到书留书

1. 打开「预约管理」，顶部汇总显示排队中、已到书、今日可领取的预约；
2. 列表按预约时间排队，`READY` 行展示"剩余保留小时"，可直接取消并说明会顺延下一位；
3. 切到「流通办理」，归还一本《雪国》——若队列里有人等待，系统自动把队首转成"已到书"并留出一册；
4. 回到「预约管理」刷新，能看到队首状态由"排队中"变为"已到书"，这就是到书留书闭环；
5. 说明保留时长由 `app.reservation.ready-hold-hours` 控制（默认 48 小时），超时自动过期并顺延。

### 2.6 统计报表

- 切换近 30 天/90 天/半年/一年/全部；
- 借阅趋势、分类借阅构成、逾期与罚款趋势、读者排行、馆藏排行；
- 点击「导出报表」下载 CSV。

## 3. 读者视角（3 分钟）

1. 退出并用 2023001 登录；
2. 首页展示个人额度、在借、累计阅读、未缴罚款；
3. 「馆藏检索」筛选分类、可借状态，借一本书；
4. 成功弹窗展示借阅日期/应还日期；
5. 「我的借阅」：
   - 页签展示全部/借阅中/逾期/已归还；
   - 对未到期图书续借（每本最多 1 次）；
   - 归还一本图书，若逾期，结果弹窗显示罚款；
6. 「我的罚款」查看规则与明细，缴纳一笔罚款；
7. 「我的预约」：
   - 页签展示排队中/已到书/已结束；
   - 对"已到书"的预约点击领取，直接跳转借阅并生成借阅记录（不再扣库存）；
   - 可取消排队中的预约，取消后队列位次实时更新；
8. 「个人中心」查看借阅证、账号信息、修改密码入口、通知偏好。

## 4. 技术与分工说明（1 分钟）

- 前端 Vue 3 + Vite + Element Plus + Pinia，后端 Spring Boot 3 + MyBatis-Plus + MySQL + Security/JWT；
- 前后端以 `/api` 契约解耦，Mock 与真实后端同契约；
- 五人按业务域纵向拆分，详情见 `docs/团队分工与协作.md`；
- 借书/还书在 Service 层事务中完成，库存与借阅记录一致；
- 登录锁定写入数据库，未引入 Redis；逾期罚款由服务端生成并固化金额。

## 5. 常见提问

| 问题 | 回答要点 |
| --- | --- |
| 为什么前端默认是 Mock？ | 方便五人并行开发和零环境演示；切 `VITE_USE_MOCK=false` 即走真实后端，页面代码不变。 |
| 为什么不用 Redis？ | 需求禁止额外中间件；登录锁定是低频强一致状态，数据库字段足够；集群可平滑迁移。 |
| 怎么保证借书不超借？ | 读者行锁 + 借阅上限校验 + 库存条件更新 + `@Transactional`。 |
| 怎么保证不重复罚款？ | 还书状态校验、记录行锁、`penalty.record_id` 唯一索引。 |
| 逾期状态是实时算的吗？ | 状态显式维护，并在查询/操作前批量刷新 `BORROWED → OVERDUE`。 |
| 前端权限能绕过吗？ | 能绕过菜单/按钮，但后端每次接口都会校验角色与资源归属。 |
| 为什么读者能自己归还？ | 需求中读者角色包含归还；归还后由服务端自动生成罚款。 |
| 预约在哪？ | 「我的预约」（读者）与「预约管理」（管理员）；种子数据里《雪国》已为 2023001 留书、2022008 仍在排队，可直接演示。 |
