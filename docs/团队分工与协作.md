# 知墨图书馆 · 五人分工与协作规范

## 1. 拆分原则

系统采用**模块化单体 + 前后端分层**。五人不是按“前端/后端”横切，而是按业务域纵向负责：
每个人同时维护自己模块的 Controller、Service、Mapper、Vue 页面与 API 封装，减少跨人等待。
公共基建由 A 统一维护，其他成员只通过稳定接口使用，避免所有人同时改 `common`、`http.js` 等公共文件。

```
调用方向：View → api/*.js → /api → Controller → Service → Mapper → MySQL
                         ↑
                   Mock adapter（前端独立演示）
```

模块之间只通过以下契约耦合：

- HTTP 接口（路径、入参、统一响应体、错误码）；
- 共享枚举/常量（角色、读者类型、借阅状态、罚款状态）；
- 认证上下文（JWT 中的 `userId`、`role`、`readerId`）；
- 业务服务公开方法（如借阅模块调用读者模块的“校验借阅资格”）。

禁止跨模块直接修改对方表、跨模块复制业务规则、在 Controller 里写业务逻辑。

> **术语说明**：文档里不特别说明时，“管理员”指系统内的图书管理员角色（`ADMIN`）；
> 涉及 GitHub 设置、分支保护、删除远程分支等操作时统称“**仓库管理员**”，固定由 A 承担。
> 两者的权限边界见 [第 8 节](#8-角色与操作权限)。

## 2. 成员与模块边界

> 实际课程设计可按 5 人姓名替换 A–E；每人至少完成一个完整垂直切片，并交叉 Code Review 另一位成员的 PR。

### 依赖顺序

```text
A 公共底座 + 认证
   ├── B 馆藏 ─┐
   ├── C 读者 ─┼── D 流通/罚款 ── E 统计/交付
   └───────────┘
```

- B、C 可并行；
- D 依赖 B 的图书库存与 C 的读者资格；
- E 依赖 B/C/D 产生的数据；
- A 提供登录与权限，是首个集成点。

│   ├── profile/     # C
│   ├── borrow/      # D

## 4. 分支与提交规范

`main` 为随时可演示的稳定分支并设为保护分支；日常开发一律走 `feature/*`，每日集成到 `develop`。本地与远程必须使用完全相同的分支名，禁止直接在 `main`、`develop` 上提交。

| 分支 | 用途 | 负责人 | 说明 |
| --- | --- | --- | --- |
| `main` | 稳定版，随时可演示 | A（保护分支） | 只接受来自 `develop` 的合并与 tag |
| `develop` | 每日集成 | 轮值（当周集成人） | 每周五主链路验证通过后合入 `main` 并打 tag |
| `feature/platform-auth` | 工程骨架、认证、权限、布局、设计系统 | A | 首个集成点，其他分支基于它联调 |
| `feature/catalog` | 图书、分类、组合检索 | B | 与 `feature/readers` 可并行 |
| `feature/readers` | 读者档案、借阅证、个人中心 | C | 与 `feature/catalog` 可并行 |
| `feature/circulation` | 借阅、归还、续借、预约、罚款 | D | 依赖 B 的库存与 C 的读者资格 |
| `feature/analytics` | 仪表盘、统计、SQL、种子数据 | E | 依赖 B/C/D 产生的数据 |

> 联调阻塞的普通问题**不再单开 `hotfix/*` 分支**：在对应模块的 `feature/*` 分支上修复，经 `develop` 验证后随当周合并进入 `main`。只有已发布版本出现线上缺陷时，才临时启用 `hotfix/<版本>-<问题>`，修完立即合回 `main` 与 `develop` 并删除该分支。

> 预约/到书留书模块已并入 `feature/circulation`（负责人 D），由 D 开 PR 合入 `develop`；不再单设预约分支。

各人的日常操作只在本人分支进行：

```bash

# ... 修改 -> 自测 -> 提交 ...

```

需要合入集成线时提交 PR 到 `develop`，由当周集成人（轮值）合并；`develop` → `main` 只在每周五验收后进行。

### 合并前检查

- [ ] 自己模块 `npm run build` / `mvn test` 通过；
- [ ] GitHub CI 的 `后端 · 测试`、`前端 · 构建` 两个检查均通过；
- [ ] 新增接口已同步到 `docs/接口清单.md`；
- [ ] 前端页面权限同时有后端鉴权；
- [ ] 金额、日期、状态流转有边界用例；
- [ ] 不提交 `.env.local`、日志、构建产物、真实数据库密码；
- [ ] 至少一位其他成员 Code Review；
- [ ] 合并到 `develop` 后跑一遍登录 → 借书 → 还书 → 罚款 → 统计主链路。

## 5. 接口契约冻结

联调前先冻结以下内容，避免各写各的：

1. 路径使用复数名词：`/api/books`、`/api/readers`、`/api/borrow-records`、`/api/penalties`；
2. 统一响应：`{ code, message, data }`，成功 `code=200`；
3. 分页统一 `page`、`size`，返回 `{ total, records, page, size }`；
4. 日期字段统一 `yyyy-MM-dd`，时间字段 ISO-8601；
5. 角色值为 `ADMIN` / `READER`，读者类型为 `UNDERGRADUATE` / `GRADUATE` / `TEACHER`；
6. 借阅状态为 `BORROWED` / `RETURNED` / `OVERDUE`，罚款状态为 `UNPAID` / `PAID`。

前端已经用 `src/mock/handlers/*` 固化了这些契约；接后端时只需要把 `VITE_USE_MOCK=false`，
页面与 `api/*` 无需改动。这是本工程实现并行开发的关键。

## 8. 角色与操作权限

先区分两类“管理员”，避免把系统角色和仓库权限混为一谈：

| 称呼 | 指谁 | 典型场景 |
| --- | --- | --- |
| **仓库管理员** | A（GitHub 仓库 Admin） | 邀请成员、分支保护、Actions、CODEOWNERS、推送 `main`、打 tag、删除远程分支 |
| **系统管理员（ADMIN）** | 系统内的图书管理员角色 | 登录后的业务功能：读者/图书/罚款管理、流通办理、统计报表 |
| **当周集成人** | 轮值成员（Write 权限） | 合并 PR 到 `develop`、周五发起 `develop → main` |
| **模块负责人** | A–E | 自己目录与自己分支的提交、开 PR、评审他人 PR |
| **全员** | 五个人 | 拉取、开 Issue、评论 PR、本地构建与自测 |

权限标记约定（本文档与 `docs/` 下其他文档统一使用）：

- 🔒 **仅仓库管理员（A）**：需要 GitHub Admin 或直接推送 `main`，其他成员无法执行；
- 🔁 **当周集成人**：合并 PR 到 `develop`、发起周版本 PR；
- ✍️ **模块负责人**：只改 4.1 节里自己负责的目录；
- 👥 **全员**：任何人可执行。

| 操作 | 权限 | 说明 |
| --- | --- | --- |
| 邀请/移除协作者、修改仓库可见性 | 🔒 A | `Settings → Collaborators` |
| 设置或修改 `main`、`develop` 保护规则 | 🔒 A | `Settings → Branches` |
| 开关 Actions、调整 workflow 权限 | 🔒 A | `Settings → Actions` |
| 替换 `.github/CODEOWNERS` 占位账号 | 🔒 A | 需直接推送 `main` |
| 推送 `main`、创建并推送 tag | 🔒 A | 可授权集成人执行，但责任仍在 A |
| 删除远程 `feature/*` 分支 | 🔒 A | `git push origin --delete <branch>` |
| 合并 PR 到 `develop` | 🔁 集成人 | CI 全绿 + 1 个 Approve 后 Squash 合并 |
| 发起 `develop → main` 周版本 PR | 🔁 集成人 | 周五主链路验收通过后 |
| 评审 PR、提出修改意见 | ✍️ 任意一位其他成员 | 对应模块负责人必须参与 |
| 推自己的 `feature/*`、开 PR、开 Issue | 👤 本人 | 只能改 4.1 节里自己负责的目录 |
| 拉取代码、本地构建、查看 Actions | 👥 全员 | 无需特殊权限 |

> 私有仓库的“仅管理员可绕过保护”等选项受 GitHub 套餐限制；课程项目建议公开仓库，见远程协作手册 1.2 节。
