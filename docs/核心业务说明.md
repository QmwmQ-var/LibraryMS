# 关键业务逻辑说明

## 1. 借书事务

借书是最容易出现数据不一致的链路，必须把「借阅记录」与「图书可借数量」放在同一事务里。

```java
@Transactional
public OperationResult<BorrowResultVO> borrow(UserPrincipal principal, BorrowRequest request) {
    // 1. 确定读者（读者只能借给自己；管理员必须选择读者）
    // 2. SELECT ... FOR UPDATE 锁定读者行，串行化同一读者的并发借书，防止突破上限
    // 3. 校验借阅证 ACTIVE
    // 4. 校验图书存在、availableCopies > 0
    // 5. 校验在借数量 < maxBorrow（本科 5 / 研究生 10 / 教师 15）
    // 6. 校验未重复借阅同一本书
    // 7. 条件更新库存：UPDATE book SET available_copies=available_copies-1
    //    WHERE id=? AND available_copies>0
    // 8. 写借阅记录（BORROWED，due_date=借出日+读者类型借期，快照读者/图书信息）
}
```

关键点：

- **读者行锁**防止同一读者同时发起多笔借书把额度突破；
- **条件更新 + 影响行数判断**防止库存被并发扣成负数；
- 任一步抛异常，Spring 回滚整个事务；
- 借期按读者类型计算：本科生 30 天、研究生 60 天、教师 90 天。

对应文件：`backend/src/main/java/com/university/library/service/BorrowService.java`，
Mapper 中的 `selectByIdForUpdate`、`decrementAvailable`。

## 2. 还书与罚款

### 2.1 还书流程

```text
锁定借阅记录
  ├── 记录不存在：404
  ├── 非 BORROWED / OVERDUE：400（已归还，防重复操作）
  ├── 权限：管理员或记录所属读者
  ├── return_date = 今天，status = RETURNED
  ├── available_copies = min(total_copies, available_copies + 1)
  ├── 若有排队预约：队首 PENDING → READY，available_copies - 1（为该读者留书）
  ├── overdueDays = max(0, return_date - due_date)
  └── overdueDays > 0 且尚未生成罚款
        amount = overdueDays × ratePerDay
        写入 penalty（UNPAID，保存 ruleRate 快照）
```

幂等保障：

1. 记录行锁 + 状态校验，重复还书直接拒绝；
2. `penalty.record_id` 唯一索引，即使出现异常并发也只能生成一笔罚款；
3. 库存增加使用条件更新 `available_copies = available_copies + 1 WHERE available_copies < total_copies`，避免异常情况下库存超过馆藏总量。

### 2.2 罚款计算

```
逾期罚款 = 逾期天数 × 每日费率
每日费率：app.penalty.rate-per-day，默认 0.50 元/天
```

- 逾期天数以**应还日期次日**开始计算；`ChronoUnit.DAYS.between(dueDate, returnDate)`。
- 金额生成时用 `BigDecimal` 固化到 `penalty.amount`，同时保存 `rule_rate` 快照；
  后续修改费率不会改变历史罚款。
- 罚款在**归还时一次性生成**，而不是页面实时计算；页面展示的“预计罚款”只用于提醒。
- 缴纳时状态从 `UNPAID → PAID`，记录 `paid_at / paid_by / payment_channel`，重复缴纳返回 400。
- 管理员记为 `CASH`（到馆缴纳），读者自助演示记为 `ONLINE`。

## 3. 预约与到书留书

预约解决"书全被借走时读者先排队、还书后自动替队首留书"的问题，状态机如下：

```text
PENDING（排队中）──还书后成为队首且有余量──> READY（已到书，保留 48 小时）
READY ──读者到馆借书──> FULFILLED（已借出，回写 borrow_record_id）
PENDING / READY ──取消──> CANCELLED
READY ──超时未取──> EXPIRED（释放留书并顺延下一位）
```

关键规则：

| 规则 | 实现 |
| --- | --- |
| 只在无可借副本时可预约 | `available_copies = 0` 才允许，否则提示"请直接借阅" |
| 借阅证须正常 | `card_status = ACTIVE`，挂失/注销直接拒绝 |
| 不可重复预约同一本 | 同一读者同一本书只允许一个 `PENDING/READY` 记录；已在借该书也不可预约 |
| 同时最多 5 个有效预约 | 统计该读者 `PENDING + READY` 数量，超限返回 400 |
| 先到先得 | 队列按 `requested_at` 升序，`queuePosition` 由同书更早的有效预约数推算 |
| 还书自动留书 | `promoteNextReady`：还书恢复库存后，若仍有可借副本，把队首 `PENDING` 转 `READY`、`available_copies - 1`（这一册为读者保留） |
| 领取不再扣库存 | `BorrowService.borrow` 检测到 `READY` 预约时跳过 `decrementAvailable`，直接写借阅记录并把预约置为 `FULFILLED` |
| 取消/过期释放留书 | `READY` 转 `CANCELLED/EXPIRED` 时 `available_copies + 1`，随后再提升下一位 |
| 并发安全 | 预约时 `selectByIdForUpdate` 锁读者行；取消/领取/过期锁预约行；留书再取用 `decrementAvailable` 条件更新兜底 |

`book.reservation_count` 缓存 `PENDING + READY` 数量：读者预约时 +1，领取/取消/过期时 -1；
续借校验读这个字段，因此"被预约的书不能续借"无需联表。

对应文件：`backend/src/main/java/com/university/library/service/ReservationService.java`，
相关方法 `create / cancel / promoteNextReady / fulfill / refreshExpired`；
`BorrowService.borrow` 与 `returnBook` 分别调用 `findReadyReservation`、`promoteNextReady`。

## 4. 续借

续借不改变书籍库存，只延长应还日期：

| 规则 | 实现 |
| --- | --- |
| 最多 1 次 | 校验 `renew_count < 1`，成功后 `renew_count + 1` |
| 已逾期不可续借 | 先刷新逾期状态，`OVERDUE` 直接拒绝 |
| 未被他人预约 | 校验 `book.reservation_count == 0`（有排队/已到书的预约时禁止续借） |
| 延长一个借阅周期 | `due_date = due_date + 读者类型借期`（不是从今天开始加） |
| 只有本人或管理员可操作 | `canOperate(principal, record)` |

## 5. 登录认证与失败锁定

### 5.1 登录流程

```text
POST /api/auth/login
  ├── 参数非空校验
  ├── 按 username 查询用户并加行锁（SELECT ... FOR UPDATE）
  ├── 账号不存在：记录失败日志，返回"账号不存在"
  ├── 账号 DISABLED：返回 403
  ├── 在锁定期内：返回 423 + 剩余分钟
  ├── BCrypt.matches 校验密码
  │     ├── 失败：failed_attempts + 1
  │     │     └── 达到 3 次：locked_until = now + 15min，记日志，返回 423
  │     └── 成功：清零 failed_attempts / locked_until
  ├── 写 login_log（账号、角色、IP、成功/失败、时间）
  └── 签发 JWT（sub=userId，claim role/username；readerId 由过滤器按 userId 实时查询）
```

### 5.2 为什么用数据库实现锁定，不用 Redis

- 需求明确禁止额外中间件；
- 登录锁定是**低频写、强一致**的状态，数据库完全够用；
- 字段持久化后，服务重启不会丢失锁定状态；
- 在集群环境中，多实例共享同一数据库也能保持锁定语义（代价是一次行锁写）。
  若未来并发量增大，可无侵入地迁移到 Redis，并保持接口不变。

### 5.3 JWT 与无状态安全

- `JwtAuthenticationFilter` 解析 `Authorization: Bearer`，校验签名、有效期、issuer；
- 将 `userId`、`role`、`readerId` 放入 `UserPrincipal`；
- 请求不创建 Session，服务端不保存 Token；
- 前端 Axios 请求拦截器统一附加 Token，401 时清理本地登录态；
- 退出登录由前端删除 Token；如需强制失效，可扩展 Token 版本号/黑名单（预留）。

### 5.4 接口级权限

- Spring Security 方法注解：`@PreAuthorize("hasRole('ADMIN')")`；
- 读者访问“我的借阅/我的罚款/读者详情/归还/续借”时，Service 再次校验
  `principal.readerId() == 资源.readerId`，防止越权；
- 前端路由 `meta.roles` 与按钮显隐只是体验优化，**不能替代后端鉴权**。

## 6. 状态流转与统计口径

| 状态 | 含义 | 进入条件 |
| --- | --- | --- |
| `BORROWED` | 借阅中 | 借书成功 |
| `OVERDUE` | 已逾期 | 定时/查询前刷新：`due_date < 今天` 且未归还 |
| `RETURNED` | 已归还 | 还书成功（含逾期归还） |

- 逾期状态由 `OverdueService.refresh()` 在查询/操作前批量刷新，保证按钮和列表状态一致；
- 逾期统计：当前 `OVERDUE` 记录数 / 在借记录数作为参考逾期率；
- 借阅趋势按 `borrow_date` 月份聚合，归还趋势按 `return_date` 聚合；
- 借阅排行榜按 `borrow_record` 统计次数；分类构成按图书分类聚合；
- 罚款趋势按 `penalty.created_at` 聚合，金额与笔数分开。

## 7. 前端交互与接口契约

### 7.1 角色与路由

- 登录后 Pinia 保存 `token + user`，`user.reader` 提供读者额度、借阅证状态；
- 路由 `meta.roles` 控制访问；侧边栏按角色动态生成菜单；
- 页面内按钮按角色显隐：管理员看到编辑/删除，读者看到借阅/续借/归还/缴纳；
- 刷新页面时，路由守卫调用 `/auth/me` 恢复用户信息。

### 7.2 Mock 与真实后端切换

```text
VITE_USE_MOCK=true   → Axios 自定义 adapter 接管 /api，浏览器 localStorage 持久化
VITE_USE_MOCK=false  → 请求经 Vite proxy / Nginx 发往 Spring Boot
```

页面与 `src/api/*.js` 在两种模式下完全不变；Mock 的路径、状态码、字段与后端严格对齐，
使前端可以脱离后端并行开发，也让答辩演示不依赖数据库环境。

### 7.3 关键交互反馈

- 借阅/归还/续借/缴纳都有二次确认、加载态、成功结果弹窗；
- 失败时展示后端业务 message（如“已达借阅上限（5 本）”“该图书仍有未归还副本”）；
- 日期、库存、额度、罚款金额在操作后即时刷新；
- 顶部通知根据角色展示逾期、待缴罚款、库存不足、临期提醒；
- 统计页支持近 30 天/90 天/半年/一年/全部切换与 CSV 导出。

## 8. 配置项

| 配置 | 默认值 | 说明 |
| --- | --- | --- |
| `DB_HOST / DB_PORT / DB_NAME / DB_USERNAME / DB_PASSWORD` | localhost / 3306 / libraryms / root / 空 | 数据库连接，可被环境变量覆盖 |
| `JWT_SECRET` | 开发默认 | 生产必须覆盖，至少 32 字节 |
| `JWT_EXPIRE_MINUTES` | 720 | Token 有效期 |
| `app.penalty.rate-per-day` | 0.50 | 每日罚款费率 |
| `app.reservation.ready-hold-hours` | 48 | 到书后为读者保留的小时数，可用 `RESERVATION_HOLD_HOURS` 覆盖 |
| `app.reservation.max-active-per-reader` | 5 | 每位读者最多同时持有的有效预约数 |
| `app.login.max-fail-attempts` | 3 | 连续失败锁定阈值 |
| `app.login.lock-minutes` | 15 | 锁定时长 |
| `app.cors.allowed-origins` | 本地前端地址 | 禁止使用 `*` |

## 9. 已知边界与后续扩展

- 预约已实现（排队、到书留书、领取、取消、过期），暂不支持指定取书馆藏地、邮件/短信到书提醒；
- 密码找回、短信/邮件通知、头像上传为后期扩展；
- 在线支付为模拟操作，真实支付需增加支付单、回调验签与对账；
- 统计查询在演示数据量下使用内存聚合，数据量增大后应改为 SQL 聚合/物化视图；
- 借阅记录与罚款查询未做归档，生产可增加按学年归档策略。
